# Interferometer Delay Model

Модель геометрической задержки сигнала для РСДБ-коррелятора (перенос ARIADNA с Fortran на
C++). По заданию коррелятора `.cfx` и орбите космического телескопа `.scf` считает
**полиномы задержки** и **полиномы координат `u,v,w`** всех станций сеанса и пишет их в
файлы формата эталона.

Учитывается: геометрическая задержка в вакууме + релятивизм (эффект Шапиро от Солнца, Луны и Земли, аберрация,
члены для наземно-космических баз), твердотельные приливы и прилив полюса, океаническая
и атмосферная нагрузка, термодеформация антенн, тропосфера (стандартная атмосфера),
а для космического телескопа — релятивистский **ход бортовых часов** относительно наземных.
Расчёт **посканный**: у каждого скана свой источник; станция считается только в тех сканах,
где она участвует. Для космического телескопа пересчитываются **TIMEOFS** (задержка сброса
сигнала на пункт приёма) и пишется новое задание `<cfx>_p.cfx`.

## Что нужно (один раз)

1. **MinGW-w64** в `PATH` (нужны `g++`, `gcc`, `ar`). Проверка: `g++ --version`.
2. **Файл эфемерид** JPL DE440 `linux_p1550p2650.440t` в `external/dephem-master/`
   (не в git из-за размера ~112 МБ). Каталоги (EOP, нагрузки, ITRF) уже лежат в
   `external/catalogs/`.

Подробности сборки, состав модулей и диагностика — в [BUILD.md](BUILD.md).

## Использование

```
delay_tool <cfx> [scf] [out_dir] [block_sec=60] [degree=5] [tropo=1] [recv=PUSHCH22]
```

| аргумент | смысл |
|---|---|
| `<cfx>` | файл задания коррелятора |
| `[scf]` | орбита космического телескопа (CCSDS OEM). **Необязателен**: если не указан (или `-`), путь берётся из cfx (`ORB_FILE`); указывайте, чтобы подставить свой файл (напр. при проверке на своём компьютере) |
| `[out_dir]` | каталог для выходных файлов. **Необязателен**: если не указан (или `-`), берётся из cfx (`%W`), а имена файлов — из cfx (`POLY_FILE`); если у станции имя не задано, генерируется `<станция>_<диапазон>.txt` |
| `block_sec` | длина блока полинома, с (по умолчанию 60) |
| `degree` | степень полинома (по умолчанию 5 → коэффициенты P0..P5) |
| `tropo` | `1` — с тропосферой (по умолчанию), `0` — только геометрия в вакууме |
| `recv` | имя пункта приёма в `ITRF2005_2.CAT`. По умолчанию `auto` — определяется по префиксу файлов данных космоса (`PUSH…`→`PUSHCH22`, `GBT…`→`GBT_VLBA`); можно задать явно |

Эфемериды и каталоги находятся автоматически (относительно текущего каталога и
родительских уровней), запускать можно из любой папки.

**Пример** (данные лежат в `example/`) — со своим файлом орбиты:
```powershell
.\delay_tool.exe example\GVLBI_RAKS01A0_L_20140423T130000_ASC_V1.cfx `
                 example\RA140423_1200_v02.scf  out_poly
```

**На корреляторе** можно не указывать ни орбиту, ни каталог — всё возьмётся из cfx
(`ORB_FILE` и `%W`):
```powershell
.\delay_tool.exe task.cfx
```

На выходе для каждой станции — два файла: полиномы задержки (`<станция>.txt`) и полиномы
координат `u,v,w` (`<станция>_uvw.txt`, строка `Pk = u, v, w`, в секундах — коррелятор
кладёт их на uv-плоскость). При наличии космоса дополнительно пишется `<cfx>_p.cfx`
с пересчитанными TIMEOFS.

## Встраивание в свой код (библиотека C/C++)

Модель — это C++-библиотека в пространстве имён `ariadna`. Весь публичный API объявлен в
**`src/functions.h`** (структуры — в `src/structures.h`, константы — в `src/constants.h`).
Чтобы встроить, ничего в модели менять не нужно: подключаешь заголовок, собираешь свой код
со всеми модулями `src/*.cpp` (+ SOFA + dephem) и вызываешь функции.

**Точки входа (от высокоуровневой к низкой):**

| функция | что делает |
|---|---|
| `init_ephemeris(path)` | загрузить эфемериды JPL — **один раз** за процесс, до остальных вызовов |
| `process_task(cfx, scf, out_dir, eop, block, degree, sample, tropo, recv)` | по заданию + орбите посчитать полиномы задержки и `u,v,w` **всех** станций и записать файлы (то же, что делает `delay_tool`) |
| `compute_task_polys(cfx, scf, eop, block, degree, sample, tropo, out)` | то же **в памяти, без файлов** → `TaskPolys{delay, uvw}` (векторы `StationPoly`/`StationUvw` по станциям). Отдельный модуль-адаптер [`src/delay_api.h`](src/delay_api.h); на нём же построен Python-модуль |
| `compute_station_poly(st, src, …, &uvw)` | полиномы **одной** станции в памяти → `StationPoly` + `StationUvw`; коэффициенты в `poly.blocks[b].coef[k]`, `uvw.blocks[b].u/v/w[k]` |
| `process_ariadna(…, results)` / `compute_delay_obs(…)` | сами **значения задержки** (не полиномы) на заданные моменты → `std::vector<DelayResult>` / одно наблюдение |

То есть можно получать **и полиномы, и сами задержки — по потребности**. Рабочий пример —
[`examples/use_as_library.cpp`](examples/use_as_library.cpp).

**Сборка своего кода.** Внутри репозитория build-скрипт собирает любой main с полным набором
модулей:
```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 examples\use_as_library.cpp
```
Для **внешнего** проекта соберите статическую библиотеку из всех модулей `src/*.cpp` и
линкуйте её вместе с `libsofa.a`:
```sh
g++ -std=c++17 -c -I./external/eigen -I./external -I./external/dephem-master/include \
    -I./external/sofa/20190722/c/src \
    src/*.cpp external/dephem-master/include/dephem/EphemerisRelease.cpp
ar rcs libariadna.a *.o
# ваша программа:
g++ -std=c++17 -I<пути выше> your_program.cpp libariadna.a \
    external/sofa/20190722/c/build/libsofa.a -o your_program
```

## Метка времени для TIMEOFS: как подать свои значения

**TIMEOFS** — задержка сброса сигнала с космического телескопа на наземный пункт приёма.
Модель считает её на определённый момент времени; этот момент дальше называется **меткой
времени**. Меток столько, сколько у космической станции строк `FILExx` в задании: по одной
на файл данных. Результат пишется в `<cfx>_p.cfx` строками `TIMEOFS<xx> = <задержка>, <метка>`.

### Откуда метка берётся по умолчанию

Из самого задания: из значения строки `FILExx` космической станции, где время закодировано
как `YYYYDDDHHMMSS` (год, день года, часы, минуты, секунды UTC). Например
`FILE00 = %P:PUSH_2014113130000.rdf` → 2014 год, 113-й день, 13:00:00 UTC → MJD 56770.541666667.
**Ничего настраивать не нужно — так работает «из коробки».**

### Переключатель источника

| состояние | что вызывается |
|---|---|
| **включено** (по умолчанию) | метка читается из текущего `.cfx` (строка `FILExx`) |
| **выключено** | метку выдаёт ваш обработчик; пока он не установлен — встроенная **заглушка**: метки нет, `TIMEOFS` не пишется, предупреждение печатается один раз |

Функции объявлены в [`src/functions.h`](src/functions.h), раздел «Метка времени для TIMEOFS»:

| функция | назначение |
|---|---|
| `set_time_mark_hook(hook)` | поставить свой обработчик; `nullptr` возвращает заглушку |
| `set_time_mark_from_cfx(bool)` | переключить источник: `true` — `.cfx`, `false` — обработчик |
| `time_mark_from_cfx()` | узнать текущее состояние переключателя |
| `get_time_mark(req, mjd)` | получить метку по текущему состоянию (модель вызывает сама; отдельно полезно в проверках) |

### Что нужно поменять в своём коде — три шага

**1. Написать функцию.** Сигнатура фиксированная (`TimeMarkHook`):

```cpp
bool my_time_mark(const ariadna::TimeMarkRequest& req, double& mjd_utc);
```

**2. Поставить её.** **3. Переключить источник.** Оба вызова — до `process_task`:

```cpp
#include "src/functions.h"
using namespace ariadna;

static bool my_time_mark(const TimeMarkRequest& req, double& mjd_utc) {
    mjd_utc = ...;          // ваша метка: UTC в MJD, сутки
    return true;            // false = метки нет, TIMEOFS для этого файла не пишется
}

int main() {
    init_ephemeris("external/dephem-master/linux_p1550p2650.440t");
    set_time_mark_hook(&my_time_mark);   // шаг 2
    set_time_mark_from_cfx(false);       // шаг 3
    process_task("task.cfx", "orbit.scf", "out_poly",
                 "external/catalogs/EOPC04_14_IAU2000_62-now.cat");
}
```

Больше в модели менять нечего: `process_task`, `compute_task_polys` и остальные точки входа
вызываются как обычно. Рабочий пример целиком — [`examples/time_mark_hook.cpp`](examples/time_mark_hook.cpp)
(собирается тем же build-скриптом: `sh build.sh examples/time_mark_hook.cpp`).

### Что приходит в обработчик

Структура `TimeMarkRequest` ([`src/structures.h`](src/structures.h)) — по её полям вы решаете,
какую метку отдать:

| поле | что в нём | пример |
|---|---|---|
| `cfx_path` | путь к текущему заданию | `example/GVLBI_RAKS01A0_L_...cfx` |
| `station` | имя космической станции в задании | `RASTRON` |
| `file_index` | индекс строки `FILExx` | `00`, `01`, `02` |
| `file_value` | значение строки `FILExx` как записано в задании | ` %P:PUSH_2014113130000.rdf` |

### Что вернуть

`mjd_utc` — момент времени **UTC в модифицированных юлианских днях (сутки)**, дробная часть
это доля суток. Перевод из календарной даты (полдень юлианского дня, поэтому `- 2400001`):

```cpp
int a = (14 - M) / 12, y = Y + 4800 - a, m = M + 12 * a - 3;
long jdn = D + (153 * m + 2) / 5 + 365L*y + y/4 - y/100 + y/400 - 32045;
double mjd = (jdn - 2400001L) + (hh*3600.0 + mm*60.0 + ss) / 86400.0;
```

Проверка: 23 апреля 2014, 13:00:00 UTC → `56770.541666667`.

Вернуть `false` — метки нет: `TIMEOFS` для **этого** файла данных не записывается, остальные
файлы обрабатываются как обычно, расчёт не прерывается.

### Из командной строки

```
delay_tool task.cfx orbit.scf out_dir --timemark=cfx      # источник .cfx (по умолчанию)
delay_tool task.cfx orbit.scf out_dir --timemark=hook     # источник — обработчик
```

Флаг можно ставить в любом месте командной строки. **Важно:** в готовый `delay_tool`
обработчик не вкомпилирован, поэтому `--timemark=hook` там включает заглушку — `TIMEOFS`
писаться не будут. Флаг нужен, чтобы проверить переключение и чтобы собрать **свой**
инструмент на базе `delay_tool.cpp` со своим обработчиком.

### Типичные случаи

* **Метки лежат в своей таблице или журнале.** Загрузите их **один раз до** `process_task`
  в `std::map` и ищите по `file_index` или `file_value`: обработчик вызывается на каждую
  строку `FILExx`, ходить из него в файл или базу не нужно.
* **Метка одна на всё задание.** Возвращайте её всегда, `req` не смотрите.
* **Метки есть не для всех файлов.** Для известных возвращайте `true`, для остальных `false` —
  задание обработается, часть строк `TIMEOFS` просто не появится.
* **Нужна поправка к тому, что в задании.** Разберите `req.file_value` сами (там строка как
  в `.cfx`), примените поправку, верните исправленную метку.

### Ограничения

* Переключатель и обработчик — **на весь процесс**, не на отдельное задание. Если в одном
  процессе считаются задания с разными источниками, переключайте `set_time_mark_from_cfx`
  между вызовами `process_task`. Менять их из нескольких потоков одновременно нельзя.
* Обработчик вызывается **только** для строк `FILExx` космической станции внутри `[$TLSC]`.
  На наземные станции и на всё остальное он не влияет.
* В Python-модуле `ariadna` точка расширения **не проброшена**: из Python доступен только
  источник `.cfx`. Чтобы отдавать свои метки, соберите свой исполняемый файл на C++
  (см. пример выше) либо допишите привязку в `python/ariadna_pybind.cpp`.

Проверить переключатель, ничего не собирая вокруг: `sh build.sh tests/test_time_mark.cpp` —
тест прогоняет все три состояния (`.cfx`, заглушка, обработчик) и возврат к `.cfx`.

### Пакетный прогон заданий: `tools/`

[`tools/batch_cfx.cpp`](tools/batch_cfx.cpp) — боевой потребитель этой точки расширения.
Проходит по дереву `корень/<эксперимент>/*.cfx`, для каждого задания кладёт полиномы
в `<эксперимент>/new_poly`, готовит `<имя>_p.cfx` рядом с исходным и правит в нём строку
вывода коррелятора на `*_p.uvx`. Модель при этом не меняется — инструмент только ставит
обработчик и вызывает `process_task`.

```sh
sh build.sh tools/batch_cfx.cpp
./tools/batch_cfx.exe Correlator_Tests                  # всё дерево
./tools/batch_cfx.exe Correlator_Tests --only=RAKS16AL_C  # одно задание
```

**Откуда он берёт метку.** Из строки `TIMEOFS` самого задания. Это не то же самое, что время
в имени файла данных: метку туда записывает отдельная программа коррелятора, которая читает
сами файлы и определяет фактическое начало записи. Данные могут начинаться не с первого
отсчёта (сбой или повреждение файла) — расхождение меньше секунды, но для задержки это очень
много. Если строки `TIMEOFS` нет, время берётся из имени файла с предупреждением;
`--no-fallback` запрещает такой откат.

Рядом два скрипта проверки, оба запускаются из корня репозитория:

| скрипт | когда |
|---|---|
| `python tools/check_marks.py [корень]` | **до** прогона: сколько у космоса файлов данных, сколько меток в заданиях, расходится ли метка с именем файла |
| `python tools/verify_batch.py [корень]` | **после**: совпали ли метки нового задания с исходным, переименован ли вывод в `*_p.uvx`, на месте ли все полиномы |

## Использование из Python

Есть **готовый нативный модуль** `ariadna` (pybind11) поверх адаптера
[`compute_task_polys`](src/delay_api.h) — считает полиномы **в памяти, без файлов**, и
отдаёт их прямо в Python. Отдельный модуль-адаптер (`src/delay_api.cpp`) не меняет остальной
код модели.

**Сборка модуля** (нужны `g++`, `pip install pybind11`, Python с dev-заголовками):
```powershell
powershell -ExecutionPolicy Bypass -File .\python\build_pybind.ps1   # Windows
sh python/build_pybind.sh                                            # Linux / Git Bash
```
Соберётся `ariadna.pyd` (на Linux — `ariadna.so`) в корне репозитория.

**Использование:**
```python
import ariadna
ariadna.init_ephemeris("external/dephem-master/linux_p1550p2650.440t")   # один раз
res = ariadna.compute_task_polys("task.cfx", "orbit.scf",               # orbit="" -> из cfx
        eop="external/catalogs/EOPC04_14_IAU2000_62-now.cat",
        block=60, degree=5, sample=6.0, tropo=True)
for sp, uv in zip(res.delay, res.uvw):       # по станциям
    for b in sp.blocks:                      # блоки полинома задержки
        b.mjd, b.utc_start, b.source, b.coef # coef = [P0..P5] (список float -> np.array)
    for b in uv.blocks:                      # блоки координат u,v,w
        b.u, b.v, b.w                        # по осям, списки [P0..P5]
```
Полный пример — [`python/example.py`](python/example.py) (`python python/example.py`).
Так можно получать в Python **и полиномы, и сами задержки** (значение полинома в момент `t`:
`sum(P_k * t**k)`).

**Альтернативы без сборки модуля:**
- **CLI + `subprocess`** — вызвать `delay_tool` и прочитать `<станция>.txt` / `*_uvw.txt`
  (парсинг: `telescope/order`, затем блоки `source/start/stop/P0..P5`). Работает всегда.
- **ctypes/cffi** — потребует `extern "C"` слоя; менее удобно, чем готовый `ariadna`.

Где полезно: пакетная обработка заданий, построение uv-покрытия (u,v из uvw), сверка
с эталоном, встраивание в питоновый пайплайн планировщика/коррелятора.
